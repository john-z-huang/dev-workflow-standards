# 恢复与异常工作流

发生阻塞、冲突、权限/认证/网络问题或验证失败时使用。先保留现场，再决定是否能在批准范围内恢复。

## 队列

| 步骤 | 结果 |
|---|---|
| 记录阻塞 | 有最小证据和待决定事项 |
| 处理冲突 | 只解决已批准的冲突，或保留现场 |
| 修复并重验 | 仍在批准范围内 |
| 安全停止 | 无法安全继续则报告 |

## 1. 记录阻塞

记录：

```text
STATUS=BLOCKED
ISSUE=<事实>  IMPACT=<阻止步骤>  EVIDENCE=<最小摘要>
NEED=<输入/授权/网络/认证/决定>  PRESERVED=<现场>
```

缺少输入、授权、网络、认证或权限时停在动作前；不要求用户粘贴 token，不改用浏览器绕过 GitHub 规则。

## 2. 处理冲突

- dirty tracked：停止切换、pull、worktree 创建，保留现场。
- 未跟踪文件会被覆盖：停止，不用 clean/reset/stash/删除/改名/移动消除冲突。
- 目标路径已被主分支提供：不覆盖。
- PR base/head/Issue 错误：停止推送/合并，先读取实际状态；共享分支错误用 `git revert`，不擅自改写历史。
- Git 冲突需要新业务/架构决定：停止；只有已批准内容的机械冲突可解决。
- Serena 未暴露、项目激活失败或语言服务器异常时，按 [`code-understanding.md`](../references/code-understanding.md) 降级到普通文件工具；若缺少调用链、类型关系或影响范围证据，停止并报告具体影响。

## 3. 修复并重验

记录失败命令、退出码、路径和最小错误；只在批准范围内修复并重新验证。状态只能标为 `PASS`、`FAIL`、`SKIPPED` 或 `BLOCKED`，不能把未运行写成通过；需要新决定或仍失败则停止。

## 4. 安全停止

停止时不得删除、覆盖、移动、重置、提交、推送、发消息、修改外部资源、合并、泄露凭据、使用裸 `--force` 或 `branch -D`。报告具体阻塞、证据、已保留内容和下一步所需的最小决定。阻塞解除后回到最近检查点。
